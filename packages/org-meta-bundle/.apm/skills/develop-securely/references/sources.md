# Sources and applicability

Primary reference: DSIT and NCSC, [Software Security Code of Practice, May 2025](https://www.gov.uk/government/publications/software-security-code-of-practice).
The publication provides 14 principles across four themes. It primarily addresses
commercial software supply; its audience table distinguishes internal developers
and open-source maintainers. Assess that scope before proposing local obligations.

The [NCSC Assurance Principles and Claims](https://www.ncsc.gov.uk/guidance/software-security-code-of-practice-assurance-principles-claims)
provides a more detailed evidence framework when assessing the Code. It is a linked
online reference, not included in the cached PDF. Neither document is a detailed
session-token or provider-configuration manual.

The theme guides in this skill are organization-authored application guidance,
not an exhaustive reproduction or an assertion of conformity with the Code.
Keep external provisions, adopted requirements, design choices and observed
evidence distinguishable. Record source provisions and edition when proposing
requirements; assess applicability at the layer that owns the obligation.
