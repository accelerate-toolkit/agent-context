# Change requirements and contracts

Read [specifications and compatibility](../define-requirements/references/specifications.context.md) and
[the change workflow](../define-requirements/references/specification-change-workflow.context.md).

Identify the definition authority, assigned and accepted baselines, affected
requirements, interfaces, providers and consumers. Distinguish local refinement
from changes to a received commission. Record the decision and changed observable
obligations before editing authoritative definitions.

Prepare a coherent change with fixed normative references, compatible edition
indexes, verification-plan impacts and outstanding reassessment needs. Preserve
stable IDs and historical evidence. Classify versions by consumer obligations,
not by file extension or whether text was added rather than removed.

Validate and prepare publication/handoff records. Publish or message only within
the user's authorization. If `collaborate-cross-repos` is installed, use it for
cross-repository communication; otherwise prepare the handoff for review without
assuming another skill or service is available. Publication, reassignment,
adoption and acceptance are separate outcomes.
